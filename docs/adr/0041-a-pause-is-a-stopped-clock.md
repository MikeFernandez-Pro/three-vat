# A pause is a stopped clock

A pause (#151) stops one instance's own clock at a moment while the shared clock runs on. Both bands and the crossfade between them show what they showed then, and resuming carries on from exactly there, as if the pause had never been. The pack carries it as **one value**, the moment the clock stopped, in the crossfade texel's spare `b`. Both decodes read it as `min( time, pausedAt )` ahead of every term that reads the clock, and `resolveVATFrame` does the same. An instance that is playing carries a moment past any clock there (`2^64`, finite and exact in float32), so nothing has to test whether an instance is paused. `pauseVATInstance` and `resumeVATInstance` are shaped like `turnVATInstance` ([ADR-0036](./0036-a-turn-retraces-and-the-blend-gets-a-start-of-its-own.md)): playback texture, index, time; the row read back, written, flagged alone, and returned.

## Considered options

- **An offset applied after speed**, the shape the research proposed: each band's local time less an accumulated hold. Rejected. The pack has two bands, each with its own speed, so it needs one offset per band, which is two values where one does. It also cannot stop a crossfade, because the weight is wall clock measured from the blend start ([ADR-0025](./0025-the-crossfade-is-a-second-live-band-in-the-pack.md)) and is not scaled by any band's speed. A pause mid-blend would hold both poses while the mix between them went on moving.
- **`speed: 0`**. Rejected. Zero is not "stopped where it is": it reads the band's first row, which is what `speed: 0` has always meant. Holding the current pose that way means solving a new start time, and a crossfade gets no speed to zero. Resuming would then mean remembering the speed the pack no longer holds. A chosen pose is a placed start time, then a pause, and the speed stays the clip's.
- **A paused flag beside the moment**. Rejected: it is a second value and a select the `min` already is. Stopping the clock at a moment past any clock is the same thing as not stopping it.

## Consequences

- **The pack does not widen.** Five texels per instance, as before. The crossfade texel's `b`, written as zero and read by nothing until now, carries the pause. Its `a` is still spare.
- **An unpaused crowd costs nothing measurable.** It is one `min` per vertex per decode, and a select, not a branch ([#72](https://github.com/MikeFernandez-Pro/three-vat/issues/72)). Measured on the two crowd pages at 500 soldiers, eight interleaved pairs each, best frame. Each pair served the decodes from before the pause beside the decodes with it, and nothing else differed. On WebGL the best frame was 1.870–1.905 ms before and 1.872–1.900 ms after. On WebGPU, which is bimodal on this machine, it was 1.364 ms before and 1.368–1.380 ms after in the fast mode, and 1.466–1.477 ms before and 1.472–1.474 ms after in the slow one. The ranges overlap on both renderers, well inside ADR-0016's 5% bound.
- **A turn leaves a paused instance where it is.** A paused instance is not moving, so it has nothing to retrace. Pausing a paused instance and resuming a playing one write nothing and return the row as it is.
- **`setVATInstance` clears a pause** unless the instance it is given names a `pausedAt`. A transition out of a paused instance blends from the pose the pause was showing: the band being left resumes as the blend begins, so the blend has no jump at its start.
- **`endsAt` of a paused instance is `null`** while it is short of its end. The resume moves the end out by the length of the pause.
- **The bake still ignores an action's `paused`**, now for a stated reason: a pause is a runtime state of one instance, not a clip default every instance of the clip inherits.
- **Additive, so it ships as a minor version.** There are two new exports and a new optional field, `VATInstance.pausedAt`. Every existing write means what it meant. The parity gate gains a paused instance and an instance paused mid-crossfade.
